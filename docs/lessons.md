# 旧项目经验教训（ai-vtuber-client 两周的坑，新项目开发时逐条对照）

来源：旧项目的提交记录、桥上的消息（#1100 到 #2945）、主人试玩。每条都写清"现象 → 根因 → 新项目怎么做"。

## 一、认东西

1. **树不只一种。** 现象：她只认某一种原木，或者因为背包里有云杉，就以为附近有云杉。新项目怎么做：
   - "木头"包括所有原木和菌柄：oak、birch、spruce、jungle、acacia、dark_oak、mangrove、cherry、pale_oak 的 `_log` 和 `_wood`，以及 crimson、warped 的 `_stem` 和 `_hyphae`。
   - 只说"砍树"、不指定树种时，砍最近的、实际看到的那种。
   - 背包里有什么，不能拿来推断附近有什么。
2. **没看到不等于没有。** 扫描范围、视线、区块加载都有上限。没扫到的格子要标成"未知"，不能当成"空的"或"安全的"。
3. **实体数量不等于威胁。** 洞穴里一次能扫到 40 多个怪，大多在十几、二十格之下的地底，够不着她。判断危险要看距离、高度差和能不能走到她身边，不能只数个数。
4. **木板、原木的名字要用真实 ID。** 合成和检查背包时，用 `minecraft:oak_planks` 这类完整 ID，不要用自己起的别名。

## 二、做事和结果

5. **发出去不等于做成了。** "命令已发送""路径已规划"都不算完成。判断完成，只看世界或背包的真实变化：方块确实没了、物品确实进包了、东西确实在主人旁边。
6. **挖一格不等于挖好竖井。** 只完成了一个小步骤，就不能宣布"整件事办完了"。部分完成、失败、最终完成，三者要分开汇报。
7. **掉落物要走过去捡，捡完核对背包。** 挖完原地等，东西不会自己进包。
8. **够不着就做不了。** 她走开捡东西以后，箱子可能就超出手能够到的距离了。操作方块前，先确认距离在 4.5 格以内。
9. **一个动作只能有一个执行者。** 旧项目里，几个模块同时抢着控制她的身体，结果互相取消。比如自动吃东西抢了战斗的物品栏，跟随把睡觉计划打断了。新项目里，同一时刻只能有一个动作在控制她，后来的要么排队，要么明确取消前一个，并说明原因。
10. **参数要和底层的真实上限一致。** 盖房请求了 20 格的扫描半径，桥接层只接受 16 格，结果 6 次全部失败。测试用的假实现也必须按真实上限来，不能比真的更宽松。

## 三、"不像脚本"

11. **站着不说话是最大的毛病。** 只要她停下来，就要说出原因，比如"这边没树了，我换个地方""我在等天亮"。
12. **失败一次就禁选到重启，等于她学不会。** 改成：把失败原因告诉她，短时间内不在同样条件下重复同一件事；条件变了，或者主人让她再试，就可以重来。
13. **固定台词占四成，玩家一听就出戏。** 固定台词只作兜底，主要的话由模型现说。同一句话不要短时间内重复。
14. **规则会互相打架。** 例如"自动跟上主人"把"回家睡觉"的计划冲掉了，"屋里没灯"让她一直被判在避难中，进不了"在家等睡觉"的状态。教训：不要用一条新规则去补另一条规则。
15. **空闲时只给"砍树"一个选项，她就成了砍树机器。** 能做的事要按她实际具备的能力列出来，而且不止一项。
16. **夜里不等于停工。** 夜里也让她在屋里做事、聊天、规划。睡不睡由她决定。

## 四、生活

17. **床有拒睡条件。** 床周围水平 8 格、上下 5 格内有怪，游戏就不让睡，隔着墙也一样。可以在床四周插火把防刷怪；或者先等怪离开，再去睡。
18. **跳过夜晚要所有玩家都睡着。** 主人先躺下、她再跟着睡也算，这种情况下第二天早上她照样要说起床的话。
19. **门关着时算墙。** 判断屋子是否封闭时，关着的门算墙，开着的门不算。
20. **吃东西的规则要集中在一处。** 旧项目有五套饥饿判断和三条吃东西的路径，互相矛盾。吃不吃、吃什么，交给她自己决定，饥饿和血量作为事实给她看。
21. **腐肉可以吃，但会饿肚子。** 这个副作用要让她知道，由她自己选。

## 五、测试和环境

22. **测试世界里通过不算数。** 组件测试 2000 多条都绿了，主人一上手几分钟就发现问题。验收以主人的真实环境和试玩为准。
23. **测试用的替身不能作弊。** 替身传送过、替她做过事的轮次一律作废。
24. **所有客户端都要加 `--offlineDeveloperMode`。** 不加的话，每次有玩家在聊天里说话，客户端都会去请求 Mojang 的屏蔽名单，每 120 秒卡一次，每次约 5 秒。
25. **开新测试服之前，先关掉旧的 Java 进程。** 残留的进程会把 `C:\pagefile.sys` 撑得很大。
26. **客户端和服务器一律最小化、后台运行，控制内存。** 主人会在后台打游戏（主人 2026-10-25）。
27. **主人正式版用的模组和测试版不一样。** 新项目要锁定版本，开跑时把实际加载的版本记下来。
28. **唤醒 GPT 和 DeepSeek，消息标题必须以 `[REQUEST]`、`[WAKE]` 或 `[URGENT]` 开头。** 其他写法收不到。
29. **我的会话里起不了 Java 服务器。** Java 网络初始化会报 loopback 错误，开服交给 GPT；Node 程序可以正常联网。
26. 启动时不弹窗：Mindcraft 的 `auto_open_ui` 默认会在主人浏览器里自动打开控制页面，2026-10-25 晚上因此弹了好几个页面。已改为 false，任何会弹窗、抢前台的设置一律关掉。
27. 盖房的高度要取地表，不能取她脚下的高度：她常站在自己挖的坑里或隧道里。2026-10-26 主人试玩时，房子就被盖进了地下（y=58，上面还压着土）。
28. 往上爬（pillar）每一步都要先清出头顶两格：跳起来需要两格空间，屋顶只空一格就跳不高、放不了方块。往上爬期间还要停掉寻路，暂停脱困、让位置这些反射，否则它们会在跳起和放方块之间把她挪开。2026-10-26 实测。
29. 默认值要符合主人的实际使用场景：为了半夜不出声，把语音开关默认关了，结果早上主人一开就是"没声音"。凡是临时改的默认值，主人醒来前都要改回来，或者在界面上写清楚。
30. 不要用"等于某个时刻"判断游戏时间：时间是每隔约 20 刻才更新一次。要判断"跨过了"这个时刻。2026-10-26，天亮整理因此一夜都没触发。
31. 动作被打断时也要把真实结果记下来，但不要把结果当成返回值交回去：返回值不为空，主循环就会立刻再问一次模型，跟正在接管的反射抢控制权。正确的做法是直接写进她的历史，返回值仍为空。2026-10-26，脱困反射打断了收集动作，那一次的实测结果就这样丢了。
32. 包含 `\n` 的替换不要用 heredoc 里的 .cjs 或 `node -e` 写：反斜杠转义有两三层，`'\n'` 会变成文件里真正的换行。这种改动用 Edit 工具。2026-10-26 一上午踩了两次。

33. **放弃 Promise 不会停止旧动作。** ActionManager 用异步上下文保留每次动作的身体控制权：取消/结束后的续段始终看到 `interrupt_code=true`，旧 bot/寻路/发包/输出写入被隔离；`runId` 只保护最终结果是不够的。正式动作必须 await 自己的后续工作；返回后才执行的延迟拾取等写操作也会被丢弃，不能依赖它们补完成。回归：`node --test dev/gpt-3007/action-ownership.test.mjs`；真实故障注入与证据见 `dev/gpt-3007/verification-notes.md`。
33. 安全功能要实测"真的生效了"，不能只看函数被调用了：上游的 `lockdown()` 和 SES 的全局函数同名，函数里其实调到的是自己，所以沙箱从来没硬化。验收看两样：进程日志里的 `[sandbox] SES lockdown applied`，以及逃逸探针 `host.constructor.constructor("return process")()` 必须被拦下。
34. 会杀死她、伤害她的测试，不要直接拿大肥鱼本体做，用单独的测试机器人。如果非得用她本人，测完马上把这条记录从她的记忆里清掉。2026-10-26 晚上，我为了验证死亡记录里的天气，在雷雨里 /kill 了她一次。她把这次假死亡写成了一条教训："雷雨白天…09:48 那次被劈死"。时间显示的是 UTC，所以和日志里的本地时间对不上，DeepSeek 一开始还以为是她编出来的。
35. 唤醒程序判断"这一轮结束了"，要看进程退出（`exit`），不能看输出管道关闭（`close`）。2026-10-25 晚上，GPT 在一轮里启动了开发服，开发服继承了输出管道，管道一直不关。结果那一轮明明 17:51 就做完了，唤醒程序还以为它在运行，后面的消息排了一个小时没送出去。已改 `ai-vtuber-bridge/gpt-wake.mjs`。
36. 一格跳不上也可能是浮点碰撞误差：玩家半宽须与服务端 `0.6F / 2` 一致，不能用 double `0.3`；持久补丁见 `patches/prismarine-physics+1.11.1.patch`，实机证据见 `dev/gpt-3027/HANDOFF.md`。
37. 合成要核背包、网格和光标的服务端真值：输出点击也须报告消耗原料格，旧纠正包不能当新同步完成；熔炼已同步就返回，不要靠重启刷新库存（`dev/gpt-3035/HANDOFF.md`）。
36. 测试产生的东西不能混进她的数据，两条路都要堵上：
    - **日志：** 离线探针和测试机器人的 `[act]` 原来都写进了 `logs/agent.ndjson`。现在只有她本人的进程（`init_agent.js` 里调用了 `setLogOwner()`）写这个文件，其他一律写 `logs/test.ndjson`。
    - **聊天：** 测试机器人执行管理员命令时，回执会广播给所有管理员，她把"HouseTest 在…放置了方块"记成了事实。开发服上已设 `log_admin_commands false`。
    - 2026-10-26 凌晨，GPT 和 DeepSeek 各发现了其中一条。
37. 测试时不要用主人的名字（JFors）跟她说话，除非那条记录事后一定会被清掉。她把"老大说的"当作永不删除的知识，我们测试时编的"钻石藏在白桦树下""往东五十格有村庄"就成了老大的话，她还真去挖过钻石。要分清哪些是主人本人说的，看这两处：启动器日志里的 `[voice] JFors said:`（语音），服务器日志里的 `<JFors>`（打字）。通过 `dev/send.mjs` 发的测试消息不会出现在这两处。2026-10-26 凌晨查清并清理。
38. 她运行的时候不要改她的记忆文件，也不要在她运行时跑清理脚本。她的进程把"听到的话"和"教过的事"放在内存里，会把文件改动覆盖回去。清理流程固定为四步：先让她停下 → 备份 → 清理并检查 JSON 有效、条数正确 → 再启动她，并在下一次天亮时确认没有回来。2026-10-26 凌晨：第一次清理被覆盖了；另外一个一次性脚本把对象数组直接 `.join` 写进文件，把 `taught.jsonl` 写坏了，从备份恢复，丢了大约半小时里她自己整理出的几条事实。
39. 会删除东西的命令（`npm ci`、`rm -rf`、清理脚本）执行前，先打印并核对当前目录。2026-10-26 凌晨，GPT 本想在临时目录里做"全新安装"检查，结果在主项目里跑了 `npm ci`，把她正在用的 `node_modules` 清掉了。她正在运行的进程又锁着 `canvas.node`，重装卡住，只好让她停下。恢复办法：`npm ci` 会通过 postinstall 跑 `patch-package`，把 `patches/` 里的补丁全部重新打上；恢复后要逐个确认补丁已打上，再确认 canvas 能加载。
40. 重启她的进程之前，先跑 `node dev/safe-to-restart.mjs`，返回 0 才重启。脚本通过 RCON 检查两件事：血量不低于 14，16 格内没有敌对生物。日志 30 秒没有战斗不能算安全。2026-10-27 02:28，我在她残血、旁边有骷髅的时候重启了一次，她重新上线几秒就被射死了。
41. 寻路库 `bot.pathfinder.goto()` 在找不到路、而且路径为空时，会直接 resolve，不会 reject。只用 try/catch 判断"走开了没有"是不够的，走完要再看她实际站在哪。
